1) Bug grosso: “riserva OT” calcolata sui gruppi candidati, non sugli OT reali

In server/services/optimizer/phase2.ts:

calcoli totalOtGroups così:

const totalOtGroups = sortedGroups.filter(g => g.hasStraordinaria === true).length;


(linee ~371–375)

Poi, per ogni gruppo, calcoli:

const remainingOtGroups = totalOtGroups - processedOtCount;


(linea ~529)

E applichi questa regola:

if (!groupHasStraordinaria && remainingOtGroups > 0 && cleaner.canDoStraordinaria) {
  continue;
}


(linee ~555–562)

Perché questo rompe tutto

sortedGroups sono gruppi candidati generati in Phase 1.
Se hai 1 OT reale, Phase 1 può generare tantissimi gruppi che includono quell’OT (OT da sola, OT+X, OT+Y, ecc…).

Quindi totalOtGroups può diventare enorme → remainingOtGroups resta > 0 per quasi tutta la Phase 2 → di fatto blocchi quasi tutti i cleaners canDoStraordinaria per assegnare gruppi non-OT.

Se la maggior parte dei cleaners ha canDoStraordinaria = true, ti rimangono candidati pochissimi cleaners ⇒ ecco perché assegni pochissimo (tipo 6 task).

✅ Fix corretto: la “riserva” deve basarsi su OT tasks unassigned, non su “quanti gruppi OT candidati esistono”.

Patch consigliata (semplice e robusta)

All’inizio calcola l’insieme degli OT task reali:

const otTaskIds = new Set<number>();
tasksMap.forEach(t => { if (t.straordinaria) otTaskIds.add(t.taskId); });

const assignedOtTaskIds = new Set<number>();


Quando assegni un gruppo con OT, marca l’OT come assegnata:

if (groupHasStraordinaria) {
  tasks.filter(t => t.straordinaria).forEach(t => assignedOtTaskIds.add(t.taskId));
}


Poi invece di remainingOtGroups, fai:

const remainingOtTasks = [...otTaskIds].filter(id => !assignedOtTaskIds.has(id)).length;


E la riserva diventa:

if (!groupHasStraordinaria && remainingOtTasks > 0 && cleaner.canDoStraordinaria) continue;


👉 Così riservi i cleaners straordinari solo finché esistono OT reali non assegnate (non finché esistono “gruppi candidati OT”).
