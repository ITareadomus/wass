3) Backend: API / Routes (server/routes.ts)
3.1 Endpoint Caso A: “aggiungi collaboratore” (task già in timeline)

POST /api/tasks/:taskId/collaborators/add
Body: { date: 'YYYY-MM-DD', cleanerId: number }

Logica:

verifica che il task esista già in timeline (almeno 1 riga in daily_assignments_current per date+task_id)

identifica primary = il cleaner già assegnato “originario”

regola semplice: se esiste pivot con is_primary=true usalo

altrimenti: prendi il cleaner della riga esistente (unico) e impostalo primary

inserisci in task_collaborators:

primary (se manca) con is_primary=true

nuovo cleaner con is_primary=false

crea la riga di assegnazione per il nuovo cleaner in daily_assignments_current

sequence: append in coda (scelta semplice)

copia task_id + metadati necessari

ricalcolo orari per tutti i cleaners del gruppo

validazione overlap (se collisione → 409 e rollback/transazione)

3.2 Endpoint Caso B: “assegna collaboratori in blocco dai containers”

POST /api/tasks/:taskId/collaborators/assign
Body: { date: 'YYYY-MM-DD', cleanerIds: number[] }

Logica:

verifica che il task non sia già in timeline per quella data

inserisci pivot per ogni cleaner:

is_primary=false (o NULL)

crea N righe in daily_assignments_current (una per cleaner)

sequence: append in coda per ciascun cleaner

assicurati base_cleaning_time valorizzata (se null → set da cleaning_time corrente o da sorgente task)

applica durata effettiva = base / N

ricalcolo orari per ogni cleaner

validazione overlap (409 se collisione, rollback)

success → il task appare in timeline (su N righe)

3.3 Endpoint remove (opzionale ma utile)

POST /api/tasks/:taskId/collaborators/remove
Body: { date, cleanerId }

Logica:

rimuovi pivot e rimuovi la riga in timeline di quel cleaner (o marca come rimossa)

ricalcola per i rimanenti

se rimane 1 solo cleaner:

puoi decidere: eliminare pivot del tutto (non più “collaborativo”)

e se esisteva primary, non serve più

3.4 Endpoint GET info collaborazione (per UI)

GET /api/tasks/:taskId/collaborators?date=YYYY-MM-DD
→ { cleanerIds, primaryCleanerId|null, count }

4) Ricalcolo tempi e validazione overlap
4.1 Prima del ricalcolo: assicurare cleaning_time effettiva

Nel flusso che chiama recalculateCleanerTimes(...):

assicurati che l’oggetto task usi cleaning_time effettiva

base_cleaning_time non deve guidare lo scheduling (serve solo come “sorgente”)

4.2 Validazione overlap

Dopo ricalcolo per ciascun cleaner coinvolto:

controlla overlap tra intervalli (start/end) adiacenti

su collisione:

restituisci 409 con dettaglio (cleaner + task che collide)

rollback (consigliato usare transazione PG per add/assign)
