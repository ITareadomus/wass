1) Postgres: tabella cache travel time
1.1 Migrazione SQL

Crea una migration (es. server/db/migrations/xxxx_travel_time_cache.sql):

CREATE TABLE IF NOT EXISTS optimizer_travel_time_cache (
  cache_key TEXT PRIMARY KEY,
  minutes SMALLINT NOT NULL,
  source TEXT NOT NULL DEFAULT 'estimated',
  updated_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE INDEX IF NOT EXISTS idx_optimizer_travel_time_cache_updated_at
  ON optimizer_travel_time_cache (updated_at);

1.2 TTL policy (in codice)

Non serve cron: nel provider, quando leggi:

se updated_at < now() - interval '30 days' → considerala “stale” e ricalcola (upsert).

2) Implementare TravelTimeProvider (Postgres + fallback + logging)
2.1 Nuovo file

server/services/optimizer/travelTimeProvider.ts

2.2 API consigliata

async getMinutes(from, to, { phase }): Promise<number>

2.3 Cache key stabile

rounding: 5 decimali (≈1m) è ok a Milano

cache_key = "${r(fromLat)}:${r(fromLng)}->${r(toLat)}:${r(toLng)}"

2.4 Log ESTIMATED_TRAVEL_USED

Quando fai fallback:

inserisci in DB + log su optimizer.optimizer_decision

anti-spam: this.loggedFallbackKeys = new Set() e logga solo la prima volta per key/run.

2.5 Query Postgres (lookup + upsert)

Lookup

SELECT minutes, updated_at
FROM optimizer_travel_time_cache
WHERE cache_key = $1;


Upsert

INSERT INTO optimizer_travel_time_cache(cache_key, minutes, source, updated_at)
VALUES ($1, $2, $3, now())
ON CONFLICT (cache_key) DO UPDATE
SET minutes = EXCLUDED.minutes,
    source = EXCLUDED.source,
    updated_at = now();
